# 因子研究引擎

本次替换旧 IC、两两/旧表达式挖掘、自动治理和权重写入器；保留 108 个特征定义、行情接口、账户执行和入场硬门槛。`scripts/factor-library.mjs` 仅作原调用接口的适配层，不再运行旧统计引擎。

## 运行

- Windows 已验证：Node 24、Python 3.11、Julia 1.12.7。Qlib 0.9.7、Alphalens Reloaded 0.4.5、arch 8、statsmodels、PySR 2.2.1。
- 安装：`npm run research:setup`（需要 uv）。锁文件包含平台条件依赖；Linux 安装及性能尚未实测。
- 正常启动仍是 `npm start`。主监控每分钟提交快照，独立 Python 进程消费、落 SQLite WAL、结算标签；重计算不阻塞 Node 交易循环。
- 首次 PySR 训练需要 Julia。该 Windows 环境已装在项目 `.runtime/julia-1.12.7`；其他环境由 juliapkg 初始化，亦可指定 `PYTHON_JULIAPKG_EXE`。
- 历史导入：`npm run research:import -- DIRECTORY [last-bars]`；目录含 `{symbol,klines:[Binance格式行]}` 的 `.json.gz`，至少8个币种。无 last-bars 限制时导入全部；不会下载、编造缺失行情。
- 原始账户、登录会话和旧研究状态不删除；新数据库在 `SIGNAL_RUNTIME_DIR/factor-research`，旧 IC 不导入。

## 同服务器资源预算（显式启用，本地保持原配置）

默认 `standard`，不根据 Windows/Linux、内存大小自动限流。本次改动不修改任何实际 `.env`。
仅在服务器 monitor **和** dashboard 服务的环境中设置 `FACTOR_RESEARCH_PROFILE=server-low`，重启对应服务后启用；两处应一致，避免手工请求绕过服务器预算。

| 项目 | 本地／standard | 服务器／server-low |
|---|---|---|
| 采样 | 每分钟 | 仍每分钟，不降采样 |
| 自动启动研究 | 每分钟尝试 | 至少间隔5分钟，资源退避期间不启动；不排队按钮请求 |
| IC重评 | 配置规定，默认60分钟 | 同左，立即评估仍可强制；不放宽统计门槛 |
| 面板 | 最近730天 | 先按目标周期取固定桶内首个时点，再保留最近90天内最新至多12000行；每个时间截面保持完整 |
| 单轮消费 | 全部收件包／成熟标签 | 至多10包，每包至多8MiB；每周期至多2000条标签，已提交部分可恢复 |
| 数值线程／PySR | 原有设置 | 数值线程1；PySR 2轮、1种群、最近100个训练时间批次、fit 30秒 |
| 整轮时限 | 原有10／30分钟 | 独立监督进程300秒，包含导入数值库与Julia，不仅是fit |

服务器执行路径：Node任务锁 → `systemd-run --user --wait --pipe --collect` → 用户级独立服务中的标准库Python监督进程 → 同一服务控制组中的数值研究。生产Node仍在原来的系统服务控制组；需要对应用户已启用linger及用户总线，systemd≥254、cgroup v2的memory/cpu/pids控制器可用。
每个研究服务固定 `MemoryMax=384M`、`MemorySwapMax=0`、`CPUQuota=50%`、`TasksMax=32`、`RuntimeMaxSec=330`、`KillMode=control-group`、`OOMPolicy=kill`。数值导入前再次核对实际控制组及四项限额；启动器、用户总线或限额异常时记录退避，绝不改走无限额Python。通过 `env -i` 只传研究所需的白名单环境，不复制账户密码、API密钥或生产proxychains注入。
父进程检查使用请求Node的PID及`/proc`启动标识，不把systemd管理器误认为请求者；请求者退出或PID复用会终止任务。显式停止/超时会停止本任务的用户服务；启动器异常退出也按精确unit名清理，保留错误信息及至少一个硬时限长度的退避。正常报告记录实际控制组限额，任务状态记录unit名。
启动前检查 `/proc/meminfo` 的 MemAvailable≥512MiB、memory PSI some avg10<1%、I/O PSI some avg10<10%、交易心跳≤15秒、最近决策完成≤60秒且连续失败为0。
运行时每2秒检查；可用内存<256MiB、研究进程组RSS≥450MiB、压力／交易状态越界时结束整个数值进程组，记录 `deferred`、原因、观测值和5分钟退避。缺少监测数据也退避，不当作零压力。RSS轮询只是附加检查，384MiB内核上限覆盖监督器、数值进程和后代的匿名内存及计费缓存；限额不保证所有规模的任务都能完成。服务器验收命令为 `FACTOR_RESEARCH_PROFILE=server-low node scripts/test-research-user-service.mjs /绝对路径/service-status.json`，使用隔离合成数据和只读生产心跳，不修改生产账户或服务。

失败或资源中断的服务器任务不替换旧报告；只有成功退出且最终健康检查通过才原子发布新报告。SQLite提交和已消费收件包保留；标签按主键增量结算。**IC统计本身是有界窗口重算，不是已实现逐点IC缓存**；下一次继续消费未处理包／标签，未完成的统计计算重新做，不承诺从中断的某个因子继续。原始数据库不裁剪、不插值；滚动IC只表示实际覆盖数据，每个指标的 `dataWindow` 给出决策起止时间与面板行数，不声称补齐90天。时间切分、FDR、EV、发布2小时有效期和账户风控全部保留；旧报告留存不代表过期发布继续交易。

### 服务器Julia维护边界

`server-low` 默认不运行PySR；自动任务仍写观测、结算标签和评估IC/Qlib，手动挖掘显示“需维护验收”，不会因Julia未就绪而每轮阻塞数据消费。
只在另行安排的受控维护窗口完成Julia安装及**真实fit**、确认资源余量后，才设置 `FACTOR_RESEARCH_SERVER_PYSR=ready`，并同时指定已有的绝对路径 `PYTHON_JULIAPKG_EXE` 和 `PYTHON_JULIAPKG_PROJECT`（后者含Manifest.toml）。配置开关是操作者的验收声明，不是软件自行证明初始化已成功。
服务器运行时强制 `PYTHON_JULIAPKG_OFFLINE=yes`，不下载Julia或Julia包；关闭自动预编译不等于完全不存在即时编译，残余编译同样受监督时限和压力检查。此次本地测试不安装Julia，不创建ready标记，不执行服务器初始化。标准本地PySR流程不改。

验证：`npm run signal:test:research-resources`。Windows执行策略、数据库和任务状态故障注入；真实Linux进程组测试在Windows明确跳过，部署验收须在Linux补跑。取消服务器预算需移除上述服务环境配置并重启；不删除数据库、账户或历史报告。

实现依据：[Linux PSI](https://www.kernel.org/doc/html/latest/accounting/psi.html)、[Python独立进程会话](https://docs.python.org/3.11/library/subprocess.html)。

## 决策权责

| 内容 | 当前实现 |
|---|---|
| Alphalens | 5m/15m/60m/240m Rank IC；显式保留盘中时点，避开默认 `asfreq(None)` 日频重采样 |
| arch/statsmodels | 时间批次、保守有效样本数、stationary bootstrap 区间、BH-FDR、4时间折、7/30/90日滚动IC |
| Qlib | 真实 DatasetH + Ridge 训练/样本外评估；只用训练集均值/尺度；收益预测不冒充胜率，暂不生产发布 |
| PySR | 多变量表达式、固定表达式哈希/AST/训练截止时间；新表达式仅在后续快照计算并积累独立验证标签，始终隔离 |
| 自动验证发布 | 单一 Python 写入者；此模式手选只是申请；方向因子需 n_eff≥200、q≤.05、3/4同号、样本外IC与净EV下界>0；48h及100个新增前向小时批次；同簇仅一代表；组合影子EV检查 |
| 手动应用 | 配置选择方向、风险、状态各至少1个，风险层至少1个波动率估计因子（实现、区间或半波动率）；启用、参与判断、正权重同时满足；方向融合权重须大于0。跳过因子资格、观察期和发布门槛；Python仅研究，不自动调权。每个标的须三层有有效数据，整层缺失时阻止新开仓；层内部分因子缺失时剔除缺失项并重新归一化权重；Bayesian与Markowitz目录项尚无独立数值输出，不能用于凑齐层数；GARCH稳定度转为1减稳定度后才进入风险混合 |
| 模型/风险/情景 | 保留特征观察；没有以方向IC直接替换概率、止损、杠杆或配置器；原模型直接参与关闭，避免重复路径 |
| 账户 | 原概率资格、成本EV、仓位和退出硬约束仍生效；手动模式也不绕过这些门槛。状态层只下调置信度、风险层只扩大波动风险缓冲；旧模型直连路径仍关闭，避免重复参与 |

默认保持自动验证模式，HMM和成交量方向在该模式关闭。手动模式允许用户明确勾选它们，不自动代选；切换回自动验证时重新执行原限制。自动验证缺少篮子成员、配置不匹配或发布过期时，整个篮子停止影响方向。手动每层1个只是当前消费接口的最小完整性条件，不是统计上的最优数量或盈利证明；配置和实时数据齐全也不保证开仓。已有账户配置不自动切换到手动。

## 任务状态

- 立即评估强制刷新IC/研究模型与治理结果；挖掘多因子表达式额外执行PySR，表达式仍隔离。未保存设置时先提示保存。
- 每个任务记录ID、动作、触发来源、开始/结束时间、结果或错误；`tasks/<id>.json` 与最近用户任务指针持久化，自动采样任务不覆盖用户任务结果。页面每3秒轻量查询，即使正在编辑配置也更新。
- Python报告实际阶段、因子/周期计数及5秒心跳；页面显示运行、完成、失败、超时或进程消失后的中断。心跳延迟仅报告未确认推进，不假定任务成功。
- 已有进程占用时不重复启动、不隐式排队；返回当前任务并明确说明本次请求未启动。刷新页面会恢复最近请求与任务结果。进度文件Windows短暂占用会有限重试，遥测写入不使研究计算失败。

## 数据与统计边界

- 因子观测和成熟标签不依赖成交，因此零开仓也会积累研究数据。历史价量特征只保留可与实时同周期比较的指标；15m数据不生成1m指标、5m收益或历史新闻。
- 标签记录实际到期价格时间，容忍到期后90秒内第一个报价；超过容忍、未来报价、服务中断分别隔离。它不是交易所逐笔成交重演。
- 标签费用/滑点仍是估计，历史导入默认往返0.16%。验证过的 Binance 历史窗口另按实际结算费率、结算标记价格、入场价格及方向计算资金费；实时记录尚未补入该账本。影子组合不是包含并发执行与盘口冲击的最终回测。
- 新挖掘因子没有自动进入生产的后门。研究中心展示它们，但本版没有人工生产晋级入口。
- RD-Agent、CNN、Transformer、实盘交易不在本版运行链路；无证据表明堆叠它们必然优于已验证简单基线。
- 年度历史研究不是盈利证明；当前19币种构成固定研究池，并非无幸存者偏差的全市场。

## 可核验历史补齐（2026-09-06）

- 原始数据位于 `.runtime/history-backfill-20260906`，原来的 `analysis` 历史文件保持原样。
- `research/backfill_history.py` 按官方 ZIP + CHECKSUM 下载、CRC 检查、OHLCV/连续性检查，并逐根核对 1m 聚合与独立 15m 数据。旧数据冲突须由收盘归档及 REST 共同确认，差异进入审计记录。
- 范围：2025-09-01 至 2026-09-06 00:00 UTC 的 15m 行情；2026-06-01 起的 1m 行情。第一天用作粗周期预热，细周期先预热120分钟。历史特征在 UTC 整点取样，只保留真实成熟价格，不把细周期缺失填零。
- 1m 与 15m 输入分开；15m 辅助窗口只包含决策时已收盘的120根。资金特征使用 OKX 已结算且至少已过去60秒的最近20个费率（至少5个），超出可获得历史范围保持缺失。Binance 年度资金费账本独立保存，不能冒充 OKX 特征。
- `research/backfill_context.py` 验证原下载导出包的清单，恢复原消息和旧特征快照。缺少事件时间/接收时间、旧模型加工结果不进入当前训练。2026-08-30 至 09-05 的百分比深度归档保存原ZIP与小时索引；它不是 L1/L5 档位或撤单流，不能用相同因子ID代替。
- 导入器新增 `--coarse`、`--from`、`--until`、`--source` 和 `--queue-only`。先在独立 `SIGNAL_RUNTIME_DIR` 生成、结算研究库，再通过 `research/install_backfill.py` 合并；双重锁、SQLite一致性备份、不可变主键保护实时数据。只导入历史不更改账户、交易勾选、自动治理或原入场门槛。
- 所有新历史资料带来源；`research.sqlite3` 的 `meta.historical_backfill` 与 `backfill.json` 记录覆盖范围、差异及缺失原因。`verification.json`、`context-verification.json`、`installed-verification.json` 分别记录下载、上下文、实际安装验收。
- 年度负载下，IC采用批量秩相关计算（并列值取平均秩），每个因子/周期抽取8个确定性时点用Alphalens核对；测试另对完整200时点及并列值验证。真实库268组新旧结果一致至数值容差，正常后台全量重算实测约127秒，低于600秒超时；没有修改统计门槛。
